# Sprint L1.7B-Q2: State And Metadata Contract

Generated: 2026-06-01

## Purpose

Define the state and metadata rules for the future `1.1.2` target-equivalent
exit ticket.

## Required State Separation

| State | Meaning | Proof status |
|---|---|---|
| `localPracticeProgress` | skill-tree, graph, reasoning, or practice route progress | not proof |
| `advisoryShortCheckResult` | local short-check advice, currently only `1.1.1` | not proof |
| `targetEquivalentAttempt` | current `1.1.2` exit-ticket attempt | attempt only |
| `targetEquivalentProofCandidate` | all reviewed tasks answered sufficiently | candidate before gate |
| `targetEquivalentProofApproved` | human-gate-approved local proof for this paragraph output | only after `GATE-L1.7B-Q2` |
| `completionLanguageEligible` | local paragraph-completion copy may be shown | only after `GATE-L1.7B-Q2` |

No state may be inferred from math stars, route-panel progress, advisory
short-check completion, or practice-game completion.

## Metadata Contract

The future `1.1.2` source should use:

```json
{
  "surface": "target_equivalent_exit_ticket",
  "targetEquivalent": {
    "candidate": true,
    "gateApproved": false,
    "completionLanguageEligible": false
  }
}
```

The legacy `metadataAlignment.targetReadinessEvidence` field may remain as a
technical compatibility flag only if the implementation documents that the
student-facing product language is target-equivalent proof, not readiness to
try.

## Forbidden State Inferences

The implementation must fail validation or review if:

- advisory short-check completion sets target-equivalent proof state;
- self-check completion sets proof state without reviewed criteria;
- route progress sets proof state;
- completion copy appears before gate approval;
- product state implies diagnostics, adaptive routing, mastery, sequencing,
  summative pass/fail, AI decision, PV projection, Scale Gate 1, or product
  use.
