mixed-practice quality floor, and produce rendered output that a reviewer can
inspect. Student-facing source tasks, exercises, tables, graphs, answer models,
and economic conclusions must trace to the 2.1.4 integration/transfer intent or
a documented follow-up. Closure proof must include paragraph/chapter
validators, rendered output, result evidence, command evidence, lead review,
and named follow-up records for any unresolved target, graph, notation, layout,
or style issue.

## Operationalized sprint procedure

1. Record baseline from the current integrated 2.1.4 and both root package
   candidates.
2. Import only the 2.1.4 package into the canonical paragraph folder with
   canonical filenames. Stop if import would require target-source mutation or
   Chapter 2.2 work.
3. Decide how to handle the package paragraaf: either exclude it from official
   print shape or include/adapt it only as no-new-theory strategy support with
   explicit evidence. Stop for human decision if this would change the
   consolidation contract.
4. Rebuild 2.1.4 rendered output through `build_pdf.py`; rebuild Chapter 2.1
   through `build_chapter.py`.
5. Run paragraph, chapter, book, roadmap, scope-language, and sprint
   validators. Stop for correction if any validator fails.
6. Prepare import notes, result, diff summary, result JSON, and lead-review
   assignment.
7. Send the bundle to the lead review agent, apply required corrections or
   record that none were needed, and request round 2.
8. Run complete-bundle validation before marking the sprint complete or moving
   to 2.2.1.
