## Operationalized sprint procedure

1. Create the sprint plan, machine plan JSON, baseline, and roadmap/ledger row; run the sprint plan and active bundle validators before source/status edits.
2. Apply only the approved target-record, blueprint, quality-ref, and roadmap status updates. Stop if any diff touches generated lesson output, Chapter 2.2 content, `references/machine/`, or `references/external/`.
3. Run the acceptance validators, including target-registry, paragraph, chapter, book, roadmap, sprint, and diff checks. If a validator fails, make a decision record: fix only scoped status evidence, or stop and record a named follow-up.
4. Prepare result, diff summary, command log, and lead-review assignment. Complete lead review round 1, corrections, and round 2 before final closure.
5. Close only after the complete sprint bundle validator passes and the acceptance evidence supports the promotion decision.
