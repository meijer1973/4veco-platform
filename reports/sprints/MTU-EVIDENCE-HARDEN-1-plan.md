# Sprint MTU-EVIDENCE-HARDEN-1: MTU Evidence Layer Freshness

Generated: 2026-06-07

## Goal

Harden the MTU registry evidence layer so the canonical MTU catalog, JSON
projection, generated coverage reports, generator-readiness reports,
roadmap/index artifacts, and CI-visible checks agree with each other.

## Context

The non-mutating audit found that the canonical MTU markdown projection is
fresh against `references/machine/micro-teaching-units.json`: 256 total units,
253 live units, and 3 deprecated units. Several generated reports are stale:
the JSON-first report suite and reference-health dashboard still report 238
total units and 235 live units, `procedure-visual-coverage` reports 247 live
units, and the old empty-needs audit summary still reports 190 live units.

This sprint is a report-generation and checker-hardening sprint. It may
regenerate reports through intended scripts and add a read-only freshness
checker. It must not hand-edit or mutate protected `references/machine/` source
data.

## Quality Standard

Quality floor: the sprint must satisfy the specification by making the MTU
JSON projection, generated coverage reports, generator readiness outputs,
roadmap/index artifacts, and CI-visible checks agree on the current live-unit
state, or name remaining intentionally informational reports with evidence,
reason, and next action. Rendered output and student-facing lesson surfaces are
out of scope; the student-facing protection proof is that no lesson output or
student-facing authority changes. Proof must include validator/test evidence,
command-log evidence, a review gate for the generated report/checker quality,
and named follow-up work for any stale report without a generator or any
intentionally historical report.

## Operationalized sprint procedure

1. Record this plan, baseline, plan metadata, and roadmap row. Stop if the
   planning bundle cannot name generated outputs, stop conditions, or the
   protected reference boundary.
2. Run a planning-review subagent before implementation edits. Stop and revise
   the plan if it finds missing generated-output statements, weak quality
   floor, missing evidence, or missing stop conditions.
3. Add a read-only MTU evidence-layer checker that validates the markdown-to-JSON
   projection in memory and compares current live-unit counts against report
   summaries and generator-readiness summaries.
4. Run the checker before regeneration and record the expected stale-count
   failure as baseline evidence; it must fail only on stale generated reports,
   not on protected source errors.
5. Regenerate stale reports through intended scripts only. Run
   `build-unit-index.js` as the intended projection command and verify whether
   it produces no protected source change beyond its generated JSON projection.
6. Rerun the freshness checker and existing validators. If a stale report has
   no generator/checker path, stop and record the missing workflow as a
   platform gap.
7. Add the freshness checker to CI and run the full requested verification
   surface, including `npm.cmd run check:platform`.
8. Refresh roadmap/index artifacts and command-log every passed claim through
   `run-sprint-command.js`.
9. Produce result, diff summary, verification review, and a structural
   lead-review round 1, correction log, and round 2 before closure.
10. Fetch/prune origin, resolve/report behind or diverged state, commit, push,
    and inspect GitHub Actions `platform-ci / validate-platform` after push if
    a commit is made.

Stop conditions:

- Stop before any protected reference mutation without explicit human-reviewed
  authority for that exact mutation.
- Stop if no generator/report builder exists for a stale report and record the
  missing workflow as a platform gap.
- Stop if regeneration writes lesson output, source data, target exercises, or
  unauthorized product authority.
- Stop if the freshness checker can only pass by excluding an active generated
  report without a named exception and next action.
- Stop if lead review returns REVISE, FAIL, or PAUSE until corrections are
  complete.

Before commit, revert only the new checker, CI step, generated report refreshes,
roadmap/index artifacts, and sprint records from this sprint. After commit,
revert the sprint commit and rerun the pre-sprint validation surface to restore
the previous generated-report state.
