# Sprint B2-2.2.2-HARDEN: Quality Notes

## Product End-State

The intended product end-state is a student-facing printed paragraph `2.2.2 Elasticiteit en omzet` that deepens 2.2.1 by connecting price elasticity to omzet effects.

The route is:

```text
price change -> quantity change -> Ev -> elastic/inelastic -> TO before/after -> omzet conclusion -> pricing advice
```

## Non-Negotiable Requirements

- Use `TO = P x Q`.
- Anchor `TO` to totale opbrengst, with the student-facing bridge that totale opbrengst is also called omzet.
- Use before/after omzet tables.
- Preserve signed `Ev` before classifying with `|Ev|`.
- Keep old-value denominators explicit in percentage-change calculations.
- Include both elastic and inelastic cases.
- State the omzet rule for price increases and price decreases.
- Include misconception guard: a price increase does not automatically increase omzet.
- Keep advice tied to omzet, not profit or costs.
- Rebuild Chapter 2.2 with exactly 2.2.1 plus 2.2.2.

## Target Trace

The migrated 2.2.2 target asks for the cinema and petrol cases. Both are included:

- Bioscoop Lux: price from 10 to 12 euro, visitors from 500 to 420, `TO` from 5000 to 5040 euro, `Ev = -0,8`, inelastic, omzet rises slightly.
- Tankstation RouteNoord: price from 1,80 to 1,90 euro, litres from 10.000 to 9.800, `TO` from 18.000 to 18.620 euro, `Ev = -0,36`, inelastic, omzet rises.

Because both migrated target cases are inelastic, the paragraph adds a separate elastic worked example so students can see the opposite revenue effect before applying the rule.

## Mathematical Checks

- Cinema: `10 x 500 = 5000`; `12 x 420 = 5040`; `Ev = -16% / 20% = -0,8`.
- Petrol: `1,80 x 10.000 = 18.000`; `1,90 x 9.800 = 18.620`; `Ev = -2,0% / 5,6% = -0,36`.
- Elastic worked example: `30 x 2000 = 60.000`; `36 x 1500 = 54.000`; `Ev = -25% / 20% = -1,25`.
- Streaming worked example: `12 x 40.000 = 480.000`; `10 x 52.000 = 520.000`; `Ev = 30% / -16,7% = -1,8`.
