# Sprint B2-2.1.1-HARDEN: Book 2 Paragraph 2.1.1 Quality Hardening

## Goal

Rewrite only Book 2 paragraph 2.1.1 Kostenstructuren so it reaches the Book 1
printed-textbook quality floor: a motivating problem, clear theory route,
worked example, summary, student help note, staged exercises, complete answer
model, rendered output, validation, and lead-review evidence.

## Context

`B2-2.1-RETRO` repaired a mechanical validation gap and chapter layout drift,
but later quality review found that Book 2 Chapter 2.1 is still much thinner
than Book 1. The next sprint must therefore be smaller than a chapter. Human
direction on 2026-06-08 changed the textbook series to one paragraph per sprint,
starting with 2.1.1.

The current 2.1.1 files exist and validate mechanically, but the paragraph is
too short, has no Book 1-style exercise route, and does not provide enough
student-facing practice to prove the textbook quality floor.

## Quality Standard

The implementation must satisfy the active specification, preserve the Book 1
print quality floor, and produce rendered output that a reviewer can inspect.
Student-facing theory, exercises, examples, tables, graphs, and answer models
must trace to the 2.1.1 target-exercise intent or a documented follow-up.
Closure proof must include paragraph/chapter validators, rendered output,
result evidence, command evidence, lead review, and named follow-up records for
any unresolved target, graph, notation, layout, or style issue.

## Operationalized sprint procedure

1. Confirm the active roadmap and sprint ledger now use the one-paragraph cadence.
2. Record the baseline for 2.1.1 content, exercises, answer model, rendered output, and protected-data status.
3. Rewrite only 2.1.1 according to the Book 1 model. Stop and ask for a human decision if the target exercise would need source-record mutation.
4. Rebuild 2.1.1 rendered output through `build_pdf.py`; rebuild Chapter 2.1 through `build_chapter.py` if the assembled chapter needs the new 2.1.1 route.
5. Run paragraph, chapter, book, roadmap, scope-language, and sprint validators. Stop for correction if any validator fails.
6. Prepare result, diff summary, result JSON, and lead-review assignment. Send the bundle to the lead review agent.
7. Apply required corrections or record that none were needed, then obtain round 2 lead review before marking the sprint complete.
