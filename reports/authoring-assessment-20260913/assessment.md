## Next deletions and focused fixes

1. **First instruction candidate: remove the blanket ban on reusing any context from another paragraph in the chapter.** `skills/econ-exercise-builder.md:229` currently requires it; line 65 also asks for chapter context to prevent reuse. The new author rewrote three usable contexts after discovering overlap in neighbouring paragraphs. The replacements caused grammar and line-wrapping work without changing the target operations. Preserve purposeful variety, transfer and the approved target context. Review the teaching tradeoff before changing this owner requirement; do not add another exception or precedence paragraph. This observation supports a bounded deletion proposal, not a claim that varied contexts never help.
2. **Remove legacy PDF implementation recipes from routine skill reading, after checking active callers.** The layout agent consumed them even though they were marked optional. Keeping a concise scope/renderer entry and moving only still-needed recipes to an explicit reference is more promising than adding another warning not to read them. Retain the supported bounded rebuild of an existing edition; forcing renderer migration for a tiny repair would expand the task.
3. **Resolve existing exercise ZIP ownership before adding more closure machinery.** All three tasks hit the same unclassified ZIP in the lane checker. They also made different, disclosed choices about stale archive members. First establish whether these ZIPs are active downloadable products or retained historical editions. If active, classify the specific output and make its existing generation path reliable; if obsolete, retire it only after checking consumers and output obligations. Avoid a blanket ZIP exemption or a new evidence-packaging framework.

Windows long-path handling, CRLF normalization and base64-heavy raw diffs are concrete tooling costs. Small fixes to the existing builders/diff commands would remove repeated recovery work. They do not justify more agent policy. A bounded-check reporting mode may eventually help distinguish existing closure gaps from defects in a small change, but this assessment is not evidence that another validator is the first priority.

Retain the checks that caught actual problems: mathematical/source integrity, independent review, usable paper answer forms, final page inspection and pagination neighbours. The useful reduction is removing compulsory work without a task-specific benefit, not suppressing these findings.
