# Quality brief — §1.1.3 Grafiekredactie

## Why this is a reasoning game

The game does not primarily ask students to draw a graph or carry out difficult arithmetic. It asks them to reason about the evidential status of graph information:

- which observations test a claim;
- whether a value is observed or interpolated;
- how strongly a conclusion may be stated;
- when a claim overgeneralizes beyond the source.

The arithmetic is intentionally easy. The cognitive work is interpretation.

## Why this fits §1.1.3

The paragraph target combines graph/table use, interpolation and critical interpretation of a percentage claim. This exemplar turns those operations into one coherent editorial task:

```text
select evidence → qualify estimate → publish a bounded conclusion
```

## Why the interface is strong

- The graph is a first-class interactive source.
- Graph points have large hit targets and keyboard support.
- A click selects or removes evidence immediately.
- Text options randomize once and remain stable.
- The final answer is assembled by answer function rather than hidden in a textarea.
- The source remains visible on desktop.
- Feedback names the reasoning operation requiring repair.

## Common weak implementations

- use the graph only as decoration;
- repeat graph construction instead of reasoning;
- require pixel-perfect clicking;
- accept exact language for an interpolation;
- turn one interval into a universal rule;
- treat a descriptive relationship as proof of causality;
- collapse the final answer into a generic text field;
- judge quality from JSON and initial screenshots rather than interaction states.

## Golden-exemplar standard

Generated output must be judged against the playable experience. Review must include selected graph points, wrong and correct estimate states, wrong and correct final answers, mobile rendering and keyboard interaction.
