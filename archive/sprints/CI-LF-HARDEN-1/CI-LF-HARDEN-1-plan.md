# Sprint CI-LF-HARDEN-1: Line Ending And Generated Report Stability

Generated: 2026-06-06

## Goal

Reduce Windows false failures and CRLF churn for CI-checked evidence,
report, roadmap, dashboard, and sprint surfaces by adding a scoped LF policy
and a quick checker.

This sprint changes CI/build-authoring evidence only. It does not change
generated lesson output, protected references, source data, target registries,
candidate storage, PV outputs, product routes, target-equivalent proof,
diagnostics, adaptive routing, mastery/sequencing, Scale Gate 1, or
student/product use.

## Context

`CI-REMOTE-1` and `CI-REMOTE-1A` made `platform-ci / validate-platform` real
and required by branch protection. Their command logs still show recurring
Windows warnings that LF files will be replaced by CRLF. The current
`.gitattributes` only pins `reports/url-index.md`, so other evidence surfaces
remain vulnerable to recurring diff-noise and false-failure risk.

## Quality Standard

The specification quality floor is byte-stable CI evidence without widening
line-ending policy into generated lesson output:

- `.gitattributes` must target only active CI evidence, generated
  index/dashboard outputs, roadmap text, and current sprint evidence surfaces
  that are checked or regenerated by platform workflows;
- the checker must inspect matched text files, fail on CRLF, and ignore
  binary or lesson-output surfaces;
- rendered output and student-facing routes remain intentionally unchanged;
- proof must show local validators pass and `git diff --check` no longer emits
  the targeted CRLF warnings;
- any unhandled warning class becomes a named follow-up rather than hidden
  closure debt.

## Operationalized sprint procedure

1. Record the CRLF warning inventory from existing command logs and stop if the
   target warning set includes generated lesson output or binary surfaces.
2. Add scoped LF rules only for CI evidence/report/index/dashboard/roadmap
   files, then run `git diff --check` before continuing. Stop if a broad rule
   or unexpected churn appears.
3. Implement a fast checker for the selected patterns and unit tests for clean
   LF text, CRLF text, binary content, and missing/empty matches.
4. Add the checker to `platform-ci` only after local checker and Jest evidence
   prove it is deterministic and quick.
5. Run acceptance validators through `run-sprint-command.js`; stop on any
   failed validator or changed generated/protected output.
6. Complete lead-review round 1, correction log, and round 2 before closure.
7. Push and verify remote `platform-ci / validate-platform` success for the
   reviewed commit before recording final proof.
